# 小智 AI 家教 · P0–P1 阶段总结报告

## 一、项目定位

面向初中生的桌面端 AI 家教机器人。核心能力：把屏幕上的卷子或手机拍的题「看懂」，
用真人老师式的**分步引导**讲题，并支持**随时插话打断**。

技术选型：全云端 API（DeepSeek 做推理，阿里百炼做识题 / 识别 / 合成），
本地只负责采集、断句、声纹与播报。

## 二、已完成范围

### P0 · 纯文字闭环（已完成）

截图 → 通义千问-VL 识题 → DeepSeek 分步引导讲解 → 多轮追问。

### P1 · 语音链路（已完成）

蓝牙耳机 + 关键词唤醒 + ASR + TTS + 声纹打断。

## 四、实测发现并修复的问题

这一阶段最有价值的产出其实是这些问题清单。它们全部是**只有真机实测才能暴露**的。

### 致命级（功能完全不可用）

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 1 | 声纹判定永远不触发 | 把「采样点数」当成了「帧数」：600ms 应为 20 帧，实际写成 960，需等 28.8 秒 | 按 `verify_ms / frame_ms` 算帧数 |
| 2 | 自己的 VAD 整个失效 | resemblyzer 拉进 `webrtcvad` 覆盖了 `webrtcvad-wheels` 的模块文件，而该文件 `import pkg_resources`——setuptools≥81 已移除 | 锁 `setuptools<81`，验证两种来源都可用 |
| 3 | 蓝牙耳机完全打不开 | 同一副耳机在 6 个 host API 下各有一条，选中的 WDM-KS 条目在 PortAudio 下必然失败 | 按 WASAPI>DirectSound>MME>WDM-KS 排序后逐个试开 |
| 4 | 默认录音设备是「立体声混音」 | 系统默认录音设备是环回设备，录的是电脑自身声音 | 启动时报错并给出修正指引 |

### 功能级

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 5 | 听起来「两个声音在同时说话」 | `speak()` 跑在 `to_thread`，取消 asyncio task 不会停线程；`begin()` 清标志位反而让旧线程复活 | 引入播报代号（generation），`begin()` 作废旧代号 |
| 6 | 唤醒词十次有八次不灵 | ASR 把「小智」识别成「小志」「这小志」，同音字全被拒 | 同音字变体表（可配置） |
| 7 | 打断延迟会爆到 3.4 秒 | torch 声纹模型首次加载耗时 3.4 秒，却发生在打断判定路径上 | 启动时预热模型 |
| 8 | 第一次打断前会卡住 | 同上 | 同上 |
| 9 | 空 Key 时抛 SDK 难懂异常 | 客户端在 `__init__` 里构造，早于密钥校验 | 先校验密钥再构造客户端 |
| 10 | 切句切出「。」这类碎片 | 纯标点片段未过滤；逗号断点位置计算错误 | 引入内容判据与 `MIN_PIECE` |
| 11 | 只叫名字也走模型 | 剥掉唤醒词后剩「这」这种语气词被当问题送模型 | 加 `MIN_UTTERANCE_CHARS` 门槛 |
| 12 | 「我在，你说」接话时切不断 | 该路径未进入 SPEAKING 状态，不触发打断 | 走统一播报路径 |

### 环境级

| # | 问题 | 处理 |
|---|---|---|
| 13 | 耳机后连上但设备列表里没有 | PortAudio 只在初始化时枚举一次，需 `refresh_devices()` 重扫，且必须在打开任何流之前 |
| 14 | 微信文件传输助手存盘路径不固定 | 待 P2 处理 |

## 六、已知风险与未验证项

| 项 | 说明 |
|---|---|
| 声纹准确率 | 蓝牙 HFP 是 16kHz 窄带 + 耳机自身降噪/AGC，会削弱声纹特征；判定只能用 0.6 秒语音。定位是「过滤明显不是你的声音」，非严格身份认证。拿不准时一律放行 |
| 云端授权 | ASR/TTS 已真机跑通；但额度、并发上限、长时间稳定性未验证 |
| 回声自激 | 依赖蓝牙耳机物理隔绝。改用外放会自问自答 |
| 打断延迟实测 | 设计目标 0.2 秒，未做仪器测量 |
| 蓝牙 profile 冲突 | A2DP（音质好、无麦）与 HFP（能听能说、16kHz）互斥，当前选 HFP |

### P3 的设计取舍

- **掌握情况靠模型判断**：结题时用一次 LLM 调用，从整段对话里提炼
  「知识点标签 + 掌握/部分掌握/未掌握 + 一句话卡点」。每题只调一次，成本可接受。
  失败就降级成「未判定」，不影响讲题主流程。
- **掌握率只按已判定的题算**：否则未判定的题会把比例摊薄得没意义。
- **薄弱知识点只统计没掌握好的题**：已经会的不该出现在待补清单里。

### P2 需要留意的两点

- **微信收到的「图片」存成加密 `.dat`**（`msg\attach` 下 1.8 万个，非简单异或），
  读不出来。手机上必须用「**文件**」方式发送照片，不能直接发图片。
- **`msg\file` 里混着所有聊天收到的文件**，同学发来的图片也会触发提示。
  缓解方式：只提示「收到新图片」，按回车才开讲，不会直接打断你。
